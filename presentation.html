System Abstract & Architectural Triad

During natural catastrophes and in routine off-grid mountain environments across Nepal, terrestrial mobile telecommunications (NTC/Ncell) suffer severe outages or complete absence. LifeLine solves this through an autonomous, decentralized hardware ecosystem coupling Sub-GHz LoRa (433 MHz) radio links, dual-ESP32 edge DSP compute, and zero-install Web Bluetooth terminals.

1. The Humanitarian Crisis: Communication Poverty in Jumla & Karnali

SECTION 01

In the rugged Himalayan geography of Nepal, over 80% of the landmass consists of steep valleys, fragile tectonic zones, and isolated mountain settlements. In districts such as Jumla, Dolpa, Kalikot, and Humla, thousands of citizens reside in permanent telecommunication blind zones with zero cellular (NTC/Ncell) reception.

When a villager experiences a critical medical emergency—such as postpartum hemorrhage during childbirth, sudden stroke, or trail injury—the absence of telecommunication turns treatable conditions into fatal tragedies. Families must physically carry patients on wicker baskets (doko) or stretchers across mountain passes for 10 to 18 hours just to notify the nearest health post. By the time help is coordinated, it is frequently too late.

2. Dual-ESP32 Split-Core Microcontroller Architecture

SECTION 02

Standard single-microcontroller IoT nodes frequently lock up or drop radio airtime frames when concurrently running heavy digital signal processing (DSP), high-frequency floating-point vector math, GPS NMEA parsing, and LoRa spread-spectrum modulation.

To achieve fail-safe industrial reliability, LifeLine implements a Dual-ESP32 architecture, physically decoupling edge sensor sampling from long-range RF modulation across two microcontrollers interconnected via a high-speed UART telemetry bus.

Subsystem Core Dedicated Microcontroller Clock & Core Allocation Primary Responsibilities
Sensor Processing Unit (SPU) ESP32-WROOM-32D 240 MHz (Core 0: Sensors, Core 1: DSP Math) 5 Hz sensor acquisition, MPU-6050 moving average vector math, MQ-135 gas PPM thresholding, NEO-6M GPS fix decoding, quantitative health & risk calculation.
Communication Controller Unit (CCU) ESP32-WROOM-32D 240 MHz (Core 0: LoRa RF, Core 1: UART / Ring Buffer) Ring buffer UART frame parser, CRC-16 validation, LoRa SX1278 SPI modulation, exponential backoff retries, bidirectional ACK management.

3. Edge Signal Processing, Sensor Fusion & Scoring Mathematics

SECTION 03

Rather than flooding low-bandwidth radio channels with continuous raw sensor readings, the SPU executes mathematical filtering and sensor fusion directly at the hardware edge.

A. Accelerometer Moving Average & Vector Magnitude

To isolate true seismic ground tremors or catastrophic landslide displacement from accidental mechanical bumps, the 3-axis acceleration vectors ($a_x, a_y, a_z$) sampled from the MPU-6050 undergo real-time vector magnitude transformation and 10-sample circular window averaging:

A_raw = sqrt( a_x^2 + a_y^2 + a_z^2 )
A_bar[k] = (1 / N) * SUM_{i=0}^{N-1} A_raw[k - i], where N = 10 samples (at 5 Hz)
theta_tilt = arccos( a_z / A_raw ) * (180 / pi)
Equation 1: 3-Axis Vector Magnitude, 10-Sample Moving Average, and Tilt Angle.

B. Quantitative Node Health Score ($H_{\text{node}} \in [0, 100]\%$)

The device computes a self-diagnostic operational health metric determining whether sensor degradation, satellite occlusion, or battery starvation has compromised node accuracy:

H_node = 100 - P_ENV - P_GPS - P_BAT

Where:
P_ENV = 15 (if DHT sensor read fails), else 0
P_GPS = 10 (if GPS fix is invalid / 0 satellites), else 0
P_BAT = max( 0, (50 - Battery_Percent) / 2 ) (when battery drops < 50%)
Equation 2: Quantitative Hardware Health Metric.

C. Environmental Hazard Risk Score ($R_{\text{env}} \in [0, 100]\%$)

The environmental risk engine fuses atmospheric temperature, toxic combustible gas PPM, and kinetic seismic movement into an aggregated risk metric:

R_env = min( 100, R_gas + R_temp + R_seismic )

R_gas = min( 40, (Gas_PPM - 100) / 15 ) (for PPM > 100)
R_temp = (Temp - 35) * 2.5 (if Temp > 35 deg C), or (5 - Temp) * 2.0 (if Temp < 5 deg C)
R_seismic = 30 (Earthquake sustained |A_raw - 1.0g| > 0.8g for >= 15 samples), 20 (Landslide tilt > 60 deg & impact > 3.0g), 5 (minor motion)
Equation 3: Multi-Domain Environmental Risk Aggregation.

D. 48-Byte Binary Framing & CRC-16-CCITT Polynomial

To prevent payload corruption over serial UART and radio channels, telemetry is serialized into a packed 48-byte binary frame with strict byte-alignment:

// Standard 48-Byte Binary Packet Definition (SharedProtocol.h) typedef struct __attribute__((packed)) { uint8_t magic1; // 'L' (0x4C) uint8_t magic2; // 'F' (0x46) uint8_t version; // 0x01 uint16_t node_id; // Unique Transmitter ID uint8_t emergency_code; // ASCII Emergency Code ('F', 'Q', 'S', 'N') uint8_t priority; // Priority Level (1 to 5) uint8_t health_score; // 0 - 100% uint8_t risk_score; // 0 - 100% uint8_t battery_percent; // 0 - 100% int32_t lat_deg_e7; // Latitude * 10,000,000 int32_t lon_deg_e7; // Longitude * 10,000,000 int16_t alt_meters; // Altitude in meters uint8_t sat_count; // Visible satellites uint8_t gps_fix; // 1 = 3D Fix, 0 = No Fix int16_t temp_c_x10; // Temperature * 10 uint16_t humidity_x10; // Humidity * 10 uint16_t pressure_hpa; // Pressure in hPa uint16_t gas_ppm; // Gas PPM int16_t accel_x_mg; // Accel X (mG) int16_t accel_y_mg; // Accel Y (mG) int16_t accel_z_mg; // Accel Z (mG) uint16_t crc16; // CRC-16-CCITT Checksum (Polynomial 0x1021) } TelemetryPacket;

4. Sub-GHz Radio Propagation Physics & RF Link Budget

SECTION 04

Commercial 2.4 GHz Wi-Fi and 5 GHz cellular backhauls fail in mountainous topography because higher radio frequencies exhibit severe Fresnel zone obstruction and low knife-edge diffraction. LifeLine operates in the Sub-GHz 433 MHz band, providing physical wavelength properties ($\lambda \approx 69.3\text{ cm}$) capable of bending around sharp terrain ridges and penetrating dense pine forest canopy.

RF Parameter Configured Value Engineering Justification
Carrier Frequency 433.00 MHz (ISM Band) Optimal diffraction around mountain ridges with minimal path loss.
Spreading Factor SF12 (4096 chips/symbol) Maximizes receiver sensitivity down to -148 dBm for extreme range.
Bandwidth 125 kHz Industry standard balance between data throughput and receiver noise floor.
Coding Rate 4/8 (Forward Error Correction) Maximum FEC redundancy to recover damaged packets in high noise.
Transmit Power +18 dBm (~63 mW boosted) High RF output power within legal unlicensed power envelopes.
Sync Word 0x12 (Isolated Network) Prevents packet collision with commercial 433 MHz weather stations.

Link Budget Calculation

Link Budget = P_TX + G_TX + G_RX - Sensitivity_RX
Link Budget = (+18 dBm) + (2.15 dBi) + (2.15 dBi) - (-148 dBm) = 170.3 dB
Equation 4: Total System Link Budget yielding theoretical range exceeding 15 km Line-of-Sight.

6. Companion Software, Zero-Install Web Bluetooth & Cloud Dispatch

SECTION 06

Emergency responders and rural health volunteers often cannot download specialized mobile apps during disasters due to dead internet connections and restricted app store access. LifeLine solves this through a Zero-Install Web Bluetooth PWA architecture.

A. Web Bluetooth API & Nordic UART Service (NUS)

Using modern browser-level Web Bluetooth APIs, any standard smartphone connects directly to LifeLine hardware nodes via Bluetooth Low Energy (BLE). Responders can type situation reports (SITREPs), view real-time radar telemetry, and configure network channels directly from Chrome, Safari, or Bluefy without downloading an app from the Play Store or App Store.

// Web Bluetooth Nordic UART Service Configuration const BLE_SERVICE_UUID = "6e400001-b5a3-f393-e0a9-e50e24dcca9e"; const BLE_RX_CHAR_UUID = "6e400002-b5a3-f393-e0a9-e50e24dcca9e"; // Write const BLE_TX_CHAR_UUID = "6e400003-b5a3-f393-e0a9-e50e24dcca9e"; // Notify

B. Central Operations Command Portal (`/portal/`)

When an RX base station connects to a local cellular hotspot or satellite link, it flushes buffered emergency telemetry over HTTPS REST APIs to the centralized Operations Command Portal. The portal features:

  • Interactive Google Maps GIS: Real-time plotting of emergency beacons, sender GPS coordinates, and historical path trails.
  • Multi-Channel Push Engine: Automated instantaneous SMS, PHPMailer SMTP email alerts, and Firebase Cloud Messaging (FCM v1) push notifications to regional district hospitals.
  • Fleet Device Management: Live battery tracking, RF packet loss statistics, and remote firmware health monitoring.

7. Hybrid Tri-Bearer Network Roadmap (RF + GSM + Satellite)

SECTION 07

LifeLine is architected to scale from isolated village radio links into a comprehensive, nationwide emergency telecommunication backbone through a tiered tri-bearer redundancy model:

Tier Layer Bearer Medium Operating Spectrum Role in Emergency Architecture
Tier 1: Local Edge Mesh LoRa RF Mesh 433 MHz Sub-GHz Zero-cost inter-village communication linking remote households, ward health posts, and local emergency shelters without commercial telecom infrastructure.
Tier 2: Regional Cellular Relays GSM / 4G LTE Relays 850 / 900 / 1800 MHz Integrated SIM failover modules in RX Base Stations automatically bridge packets to municipal headquarters whenever a commercial mobile tower is within range.
Tier 3: Direct-to-Satellite Uplinks Satellite NTN / LEO L-Band / Ku-Band (Swarm/Iridium) Ultimate fail-safe redundancy for high-altitude glacial hazard zones (GLOF) and completely cut-off mountain valleys where no terrestrial towers can survive.
